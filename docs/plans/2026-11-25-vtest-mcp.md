# V-test MCP Server Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A local stdio MCP server with one tool, `compare_energy_contracts`, that submits usage to vtest.be and returns the cheapest contracts.

**Architecture:** Plain HTTP scraping of the public V-test form (GET home for cookie + anti-forgery token, POST multipart form to `/`, parse results HTML). Pure modules (postal codes, form building, result parsing, ranking) are unit-tested against real captured fixtures; the HTTP client takes an injectable `fetch`.

**Tech Stack:** Node 24, TypeScript (ESM), `@modelcontextprotocol/server@2.4.0`, `zod@^4.2.0`, `cheerio`, `vitest`, `@biomejs/biome` (lint).

**Spec:** `docs/specs/2026-11-25-vtest-mcp-design.md`

## Global Constraints
- MCP SDK: `@modelcontextprotocol/server` v2 (2.4.0), entry `serveStdio` from `@modelcontextprotocol/server/stdio`.
- `tsconfig.json` must set `"types": ["node"]` (SDK README requirement for TS ≥ 6).
- One POST to vtest.be per tool call. No retries, no parallel requests.
- Never return a guessed price: parse failure → tool error.
- Constants live in `src/consts.ts` (never `constants`).
- Commits: conventional, ≤100 chars per line, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Scripts: `npm test`, `npm run typecheck`, `npm run lint`, `npm run build`. All must pass before each commit.

## Review Focus
1. Postcode with several municipalities (`1570`) and no `municipality` given → error listing `Galmaarden`, `Tollembeek`, `Vollezele`, no HTTP call. (Task 1, Task 4)
2. Postcode outside Flanders (e.g. `1000` Brussels, `4000` Liège) → clear error pointing to BRUSIM / CompaCWaPE. (Task 1, Task 4)
3. vtest.be returns non-200 or a page with zero `.resultitem` (form rejected, layout change) → tool error, not an empty "no contracts" success. (Task 3)
4. Belgian number format `1.182,35` parsed as `1182.35`, not `1.18235`. (Task 2)
5. Electricity-only request (no `gas`) → `EnergyTypeGas=false`, result has no gas list. (Task 3, Task 4)

### Task 3: V-test HTTP client + form builder

**Files:**
- Create: `src/vtest-client.ts`, `src/usage.ts`, `test/vtest-client.test.ts`

**Interfaces:**
- Consumes: `parsePostalCodes`, `PostalCodeOption` (Task 1); `parseResults`, `ContractOffer`, `VtestResponseError` (Task 2).
- Produces:
  ```ts
  // src/usage.ts (zod v4 schema, reused as the tool inputSchema in Task 4)
  const usageSchema = z.object({
    postal_code: z.string().regex(/^\d{4}$/),
    municipality: z.string().optional(),
    electricity: z.object({
      day_kwh: z.number().min(0).max(100000),
      night_kwh: z.number().min(0).max(100000).default(0),
      exclusive_night_kwh: z.number().min(0).max(100000).default(0),
      digital_meter: z.boolean().default(true),
      injection_day_kwh: z.number().min(0).max(12000).default(0),
      injection_night_kwh: z.number().min(0).max(12000).default(0),
      inverter_kw: z.number().positive().optional(),
      capacity_peak_kw: z.number().positive().optional(),
    }).optional(),
    gas: z.object({ amount: z.number().min(0), unit: z.enum(["kWh", "m3"]).default("kWh") }).optional(),
    filters: z.object({ tariff_type: z.enum(["fixed", "variable", "dynamic"]).optional(), green_only: z.boolean().default(false) }).optional(),
    limit: z.number().int().min(1).max(50).default(10),
  }).refine(u => u.electricity || u.gas, "Provide electricity and/or gas usage");
  type UsageInput = z.infer<typeof usageSchema>;

  // src/vtest-client.ts
  buildForm(usage: UsageInput, postalCodeId: string, token: string): FormData;
  type VtestClient = { getPostalCodes(): Promise<PostalCodeOption[]>; compare(usage: UsageInput, postalCodeId: string): Promise<ContractOffer[]> };
  createVtestClient(fetchFn: typeof fetch = fetch): VtestClient;
  ```
- Field mapping in `buildForm` (verified working set, 2026-11-25): always send `__RequestVerificationToken`, `PostalCode=<id>`, `PropertyType=1`, `UserConsumption=2`, `IsFromIndexPage=True`, `CreateLocation=False`, `ShowModalCreateProfile=False`, `IsFromLandingPage=False`, `LocationCoupledToFluvius=False`, `ZipCodeBaarleHertog=6999`, `NumberOfResidents=3`, `UnknownMeterType=2`, `UnknownMeterCounting=1`, `SelectedMeterType=1`, `periodOptionsElek=false`, `periodOptionsGas=false`, `periodOptionsReturn=false`. Then:
  `EnergyTypeElectricity`/`EnergyTypeGas` = `"true"|"false"` by presence; `HasDigitalMeter` = digital_meter; `HasNightMeter` = night_kwh > 0; `HasExclusiveNight` = exclusive_night_kwh > 0; `UsageDay`, `UsageNight`, `UsageExclusiveNight` (rounded integers); `UsageGas` + `GasMeterUnit` (`1` = kWh, `2` = m³); `HasSolarPanels` = any injection > 0, with `InjectionDay`, `InjectionNight`; `KnowsInverterPower` + `InverterPower` (decimal with comma) when given; `KnowsCapacityElectricity` + `CapacityElectricity` (comma decimal) when given. Missing hidden fields cause HTTP 500, so keep the always-send list complete.
- Client flow: `GET VTEST_BASE_URL/` with `User-Agent: USER_AGENT` → collect `set-cookie` (`response.headers.getSetCookie()`), read token from `input[name=__RequestVerificationToken]`; cache home HTML for `getPostalCodes()` per client instance. `compare`: fresh GET (new session + token), then `POST /` with `Cookie`, `Referer`, form body; non-200 → `VtestResponseError("V-test returned HTTP <status>")`; else `parseResults(text)`.
